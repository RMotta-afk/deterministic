# Evidence-building order for the TCC

**Delivered within the final limited scope:** the [four-pillar Editor protocol](editor-four-pillars-protocol.pt-BR.md) and [live evidence](../metrics/editor-four-pillars-2026-11-14/OBSERVABILITY.pt-BR.md) measure scalar factual error, real-code relational/task accuracy, latency, and exact token counts with record relevance labels. Four paired sequences and a no-memory control completed; the measurement gate passes for these definitions. Vector had higher accuracy; graph had lower time/token consumption. This operational milestone does not close the broader long-horizon, human-validation, Cognee-integration, or generalization gates below. TTFT was explicitly removed from scope.

The claim under test is that explicit, provenance-backed relations improve accuracy and context efficiency in a growing multi-agent workflow. A null or reversed result is valid. This plan follows the architecture and comparison rules in [base.md](base.md), Sections 1, 2, 3, and 4.

The latter has a four-field observability gate, which explicitly fails the TCC-completeness condition. |

The controlled pilot measures retrieval strategy and memory representation together. It does not isolate database engine speed or prove that a graph database is inherently better. The Editor migration remains a separate feasibility case.

The final POC pair adds a deterministic evidence-grounding verdict and abstention count to every step. It completes the four-metric instrumentation for this **opaque-answer scenario**, while the PDF's broader hallucination judge and useful-context-token ratio still require independently labeled free-form outputs and token-level relevance annotations. Those remain part of a later confirmatory study, not claims established by the POC.

The real Editor follow-up attempted a blinded free-form judge. Its vector verdicts contradicted two executable checks, so its raw 0% contradiction claim is rejected. The real pair measures latency and token consumption, but neither real-code multi-hop answer accuracy nor the PDF's useful-context-token ratio. It should be treated as an operational milestone, not a final proof of all four TCC outcomes.
